# POSITIONING.md — ramita.dev V2

## Purpose

Definir cómo se posiciona `ramita.dev` frente a potenciales clientes.

Este documento es la fuente de verdad para:
- audiencia objetivo;
- propuesta de valor;
- posicionamiento comercial;
- tono;
- diferenciación;
- mensajes que deben evitarse.

No define precios, paquetes, UI ni copy final.

## Product position

`ramita.dev` es el sitio comercial personal de **Ramiro Garcia**, desarrollador web freelance.

Su objetivo principal es generar consultas de potenciales clientes que necesiten una web.

El sitio también funciona como portfolio profesional, pero los proyectos se presentan como **evidencia de capacidad**, no como fin principal.

Prioridad:
1. vender servicios web;
2. generar confianza;
3. demostrar capacidad con proyectos reales;
4. presentar a Ramiro como profesional.

## Public identity

Identidad y contacto canónicos: CONTENT.md.
El título profesional real es **Full Stack Developer**; para clientes se prioriza lenguaje como **diseño y desarrollo web**, sin fijar todavía copy final ni la jerarquía visual del título.

## Positioning statement

Ramiro ofrece **diseño y desarrollo de sitios web** para negocios, profesionales y emprendimientos que necesitan una presencia web clara y preparada para publicarse.

La oferta conecta la definición del proyecto, el diseño, la implementación y la puesta online, con un único interlocutor responsable de la entrega acordada. Ramiro puede acompañar después con ajustes, correcciones, mejoras o mantenimiento cuando se acuerde; la estabilización de la entrega y la evolución posterior tienen alcances distintos.

Esta es una definición conceptual de posicionamiento, no copy público final ni Hero.

## Target customer — confirmado 2026-09-20

No habrá nicho sectorial inicial.

Target inicial confirmado:
- pequeños negocios;
- profesionales independientes;
- emprendimientos;
- empresas que necesitan una web institucional;
- negocios con una web desactualizada;
- clientes que necesitan una landing page.

No priorizar un sector por el solo hecho de tener un proyecto de ese rubro.

Mercado natural: Argentina / Latinoamérica. Se aceptan proyectos remotos internacionales.
El sitio contempla ES / EN / PT / FR / JA, con español como fuente; no hacer claims sobre fluidez oral. Fuera de ES se aclara discretamente que Ramiro habla español y usa herramientas de IA/traducción junto con el contexto del proyecto para comunicarse y trabajar con precisión.

## Core customer problem

El cliente típico no busca “Astro”, “React”, “Tailwind” o una lista de tecnologías.

Busca resolver problemas como:
- no tener web;
- tener una web vieja o poco profesional;
- no verse bien en mobile;
- no transmitir confianza;
- no recibir consultas correctamente;
- no aparecer bien estructurado para buscadores;
- necesitar una landing para un servicio o campaña;
- necesitar llevar una idea desde planificación hasta publicación.
- necesitar presencia local en Google Maps cuando el negocio la requiera;
- necesitar una base clara y accesible para buscadores y asistentes de IA, sin garantías de visibilidad.

La comunicación debe hablar primero de esos resultados.

## Value proposition

Ramiro ofrece un servicio que conecta definición, diseño e implementación con un único interlocutor responsable de la entrega acordada.

Puede encargarse de las siguientes disciplinas según el alcance del proyecto:
- planificación;
- estructura;
- UX/UI;
- diseño visual;
- desarrollo;
- responsive;
- formularios e integraciones;
- SEO técnico;
- configuración u optimización del Perfil de Empresa de Google cuando aplique a un negocio local;
- fundamentos técnicos para buscadores y asistentes de IA, cuando correspondan;
- performance;
- publicación y hosting.

Estas capacidades son complementarias y dependen del alcance. No implican rankings, recomendaciones de asistentes, reseñas ni resultados comerciales garantizados.

La propuesta debe transmitir:
- claridad;
- criterio visual;
- autonomía;
- atención al detalle;
- capacidad técnica;
- responsabilidad sobre la entrega acordada.

## Professional profile

Hechos confirmados:

- trabaja full stack cuando el proyecto lo requiere;
- participa en UX/UI y decisiones de producto;

## Brand personality

`ramita.dev` debe sentirse:
- personal;
- directo;
- preciso;
- moderno;
- creativo sin exageración;
- profesional sin tono corporativo artificial;
- técnicamente sólido;
- accesible para alguien no técnico.

Evitar tono:
- de agencia ficticia;
- grandilocuente;
- excesivamente técnico;
- demasiado informal;
- lleno de buzzwords;
- genérico de IA.

## Voice

Preferir primera persona singular:
- “Diseño”
- “Desarrollo”
- “Trabajo”
- “Puedo ayudarte”
- “Contame qué necesitás”

Evitar:
- “Somos”
- “Nuestro equipo”
- “Nuestra agencia”
- “Líderes”
- “Soluciones innovadoras”
- “Transformamos tu visión”
- claims empresariales que no correspondan.

## Commercial hierarchy

La web debería responder, en este orden:
1. **¿Qué puede hacer Ramiro por mi negocio/proyecto?**
2. **¿Por qué debería confiar en él?**
3. **¿Qué trabajos reales respaldan esa capacidad?**
4. **¿Quién es Ramiro y cómo trabaja?**
5. **¿Cómo lo contacto?**

La presentación personal queda subordinada a la propuesta de servicio.

## Differentiation

Los diferenciadores se expresan como capacidades y forma de trabajo, no como superioridad demostrada frente a otros profesionales:

- continuidad entre diseño e implementación;
- trato directo con quien realiza el trabajo;
- criterio visual y técnico aplicado conjuntamente;
- capacidad de implementar correctamente una dirección visual externa.

No basar la diferenciación en:
- “uso IA”;
- cantidad de frameworks;
- efectos visuales;
- ser “full stack” como claim aislado.

La diferenciación debe surgir de:
- capacidad de llevar un proyecto completo;
- criterio visual + técnico;
- atención al responsive;
- integración de UX/UI, SEO y performance;
- trabajos reales;
- comunicación clara;
- experiencia visual cuidada en `ramita.dev`.

## Role of technology

Las tecnologías son evidencia secundaria.

Pueden aparecer:
- dentro de casos de estudio;
- en contexto de una decisión técnica;
- como respaldo del trabajo realizado.

No deben dominar:
- Hero;
- propuesta de valor;
- navegación;
- primera explicación del servicio.
